End-to-End System Design

🏗️ สถาปัตยกรรมระบบ 4 ระดับ (4-Tier AIoT)

การผสานการทำงานแบบไร้รอยต่อตั้งแต่ Edge Hardware จนถึง Large Language Model (LLM) บนคลาวด์

📟

1. Edge Device

ESP32-S2 (Cucumber RS)

รันอัลกอริทึม FreeRTOS 50Hz คำนวณ Signal Vector Magnitude (SVM) เพื่อตรวจจับการล้มแบบทันที ไม่ต้องรอคลาวด์

🛡️

2. Dual-Route Network

Direct LAN + Cloudflare Tunnel

ส่งตรงเข้า LAN IP (10ms Zero-latency) พร้อมระบบ Auto-Fallback สลับไป Cloudflare Tunnel ทันทีเมื่ออยู่นอกสถานที่

⚙️

3. Backend Engine

FastAPI & SQLite ORM

บันทึกประวัติการล้ม, สภาพแวดล้อม HTS221/BMP280 และคำนวณ Context Risk Matrix ความเสี่ยงลื่นล้ม

📱

4. Caregiver TMA

Caregiver Dashboard & Gemini

แดชบอร์ดธีมเขียว-ขาวสำหรับผู้ดูแล พร้อมสถานะ Wearer, กราฟแยกอุณหภูมิ/ความชื้น และ Care Assistant AI

กลไกการตรวจจับ: 3-Stage Finite State Machine

เพื่อความแม่นยำสูงสุด ระบบไม่ตัดสินจากการกระแทกเพียงอย่างเดียว แต่ต้องผ่านการตรวจสอบต่อเนื่อง 3 ขั้นตอน:

STAGE 1: Free-fall SVM < 0.70G

ตรวจจับจังหวะการทิ้งตัวหรือไร้น้ำหนักขณะเริ่มร่วงหล่น

STAGE 2: Impact Spike SVM > 2.00G

ตรวจจับแรงกระแทกพื้นภายใน 750ms หลังจากการทิ้งตัว

STAGE 3: Stillness ΔSVM < 0.50G

ตรวจสอบการอยู่นิ่งหลังกระแทกนานเกิน 500ms ยืนยันการล้มจริง

ความหน่วงต่ำระดับวินาที (~1s Latency)

ระบบประมวลผลและส่งต่อสัญญาณความเร็วสูง อัปเดตข้อมูลเซนเซอร์บนแดชบอร์ดอย่างต่อเนื่อง แจ้งเตือนฉุกเฉินและส่งเสียงไซเรนทันทีที่เกิดเหตุการณ์

ความจำการสนทนารวมศูนย์ (Unified Memory)

ประวัติการแชทเชื่อมโยงกันอย่างสมบูรณ์ ไม่ว่าจะพิมพ์ในห้องแชท Telegram โดยตรง หรือพิมพ์ผ่านหน้าจอ Mini App AI จะจำบริบทเดิมได้อย่างต่อเนื่อง

🔌 ข้อมูลเซนเซอร์ในชุดทดลอง

การเชื่อมต่อผ่าน I2C Bus เดียวกัน พร้อมระบบ Mutex ล็อกบัส

🧭

MPU-6050 (I2C: 0x68)

6-Axis Motion Tracking

วัด Accelerometer (±8G) และ Gyroscope (±500°/s) เป็นแกนหลักในการตรวจจับสภาวะทิ้งตัวและการกระแทกแบบ Real-time

🌡️

HTS221 (I2C: 0x5F)

Temperature & Humidity

วัดอุณหภูมิและความชื้นสัมพัทธ์ในห้อง หากความชื้นสูงเกิน 75% ระบบจะปรับประเมินความเสี่ยงลื่นล้มเป็น "สูง (High Risk)" ทันที

🌪️

BMP280 (I2C: 0x76)

Barometric Pressure

วัดความกดอากาศความละเอียดสูง เพื่อบันทึกบริบทสภาพอากาศรอบข้างร่วมกับอุณหภูมิเพื่อรายงานผ่าน AI

การวิเคราะห์ทางวิศวกรรม

⚠️ ข้อจำกัดและแนวทางการพัฒนาสู่ผลิตภัณฑ์จริง

โครงงานนี้เป็นชุดทดลองต้นแบบสำหรับนักศึกษา (Educational Prototype) โดยมีจุดที่สามารถต่อยอดได้ดังนี้:

1. พัฒนาจาก Threshold สู่ TinyML บน MCU

ปัจจุบันใช้อัลกอริทึม Heuristic SVM ซึ่งอาจเกิด False Positive ได้หากกระโดดลงเตียงอย่างแรง สามารถพัฒนาต่อยอดด้วยโมเดล 1D-CNN หรือ Random Forest ที่รันบน ESP32-S2 ได้โดยตรง

2. การประหยัดพลังงาน (Power Management)

เนื่องจากการเชื่อมต่อ Wi-Fi และอ่านเซนเซอร์ที่ 50Hz ใช้กระแส 120–180mA ในการใช้งานจริงควรปรับใช้ Deep Sleep ร่วมกับ MPU-6050 Motion Interrupt หรือเปลี่ยนไปใช้ BLE

3. ความเสถียรของโครงข่าย (Network Reliability)

การใช้ Cloudflare Quick Tunnel เหมาะสำหรับการทดลอง หากนำไปให้บริการจริงควรจด Named Domain ถาวร หรือใช้โปรโตคอล MQTT พร้อมระบบรับประกันการส่ง QoS 1

4. เคสอุปกรณ์และมาตรฐานกันน้ำ (IP67)

สำหรับการตรวจจับการลื่นล้มในห้องน้ำ จำเป็นต้องออกแบบ 3D Printed Enclosure ที่มีมาตรฐานกันน้ำและความชื้น เพื่อป้องกันการลัดวงจร
